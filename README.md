# Ведома — единое окно студенческих услуг в MAX

> Техническое имя в коде и инфраструктуре — `uniflow` (папка, Docker-проект, домен стенда). Название продукта — «Ведома».

Трек «Образовательные решения». Чат-бот MAX с подключённым Mini App и веб-панелью для вуза.

Репозиторий: https://github.com/Fridrix19/vedoma · команда «Пантеры», СПбГУПТД.

## Назначение решения

Студенту нужна справка, заявление или запись в деканат, и сейчас он ищет нужный отдел, форму и часы приёма
на сайте, в чатах и в деканате. Статус заявки приходится узнавать отдельно.

С сервисом «Ведома» студент пишет боту своими словами («Мне нужна справка для банка»). Бот определяет услугу и открывает
Mini App с уже заполненной формой, а чего не хватает — уточняет кнопками. Дальше студент получает статусы и готовую
справку прямо в чат MAX: настоящий PDF с электронной подписью вуза и QR-кодом, по которому банк или МФЦ проверит подлинность.

Сотрудник деканата разбирает заявки в веб-панели. Администратор вуза сам включает услуги и собирает новые
в конструкторе, без разработчика. Он же видит обратную связь студентов и узкие места процесса.

## Основной пользовательский сценарий

1. Студент открывает бота в MAX → «Войти через ВУЗ» → вход в Mini App. Профиль привязывается к аккаунту MAX.
   Пока адрес Mini App не зарегистрирован в MAX, можно нажать «Демо-вход: тестовый студент» прямо в боте.
2. Студент пишет боту: «Мне нужна справка для банка».
3. Бот отвечает: «Похоже, вам нужна справка об обучении. Обычно готовится до 3 рабочих дня» и показывает кнопку «Оформить».
4. Mini App открывается на форме, где ФИО, группа и место требования уже заполнены → «Отправить».
5. Бот пишет: «Заявка №18425 принята». Сотруднику деканата приходит уведомление «Новая заявка №18425».
6. Сотрудник в панели: «Взять в работу» → «Сформировать по шаблону» (или «Прикрепить PDF») → «Отметить «Готово» и отправить».
7. Студенту в MAX приходит сообщение «Заявка №18425 готова» с PDF-файлом и кнопкой «Проверить подпись». Справка подписана
   электронной подписью вуза, в ней штамп подписи и QR-код на страницу проверки `/verify/<номер>`. Файл можно переслать
   из MAX в банк или МФЦ. В Mini App — превью документа, отметка «Подписан электронной подписью», «Скачать PDF».
8. Бот просит оценить услугу (1–5). Оценка и комментарий попадают на дашборд вуза в раздел «Обратная связь и узкие места».

Дополнительные ветки: сотрудник запрашивает уточнение → статус «Нужны данные» → студент дополняет заявку
в Mini App; отказ с причиной; каталог услуг в Mini App без бота.

## Состав и архитектура

Один контейнер `app` (Node.js 22):

```
MAX (мобильная и веб-версия)
 ├─ чат с ботом ─── long polling ──► server/bot.ts ──► Bot API MAX (platform-api2.max.ru)
 └─ Mini App (dist/miniapp.html) ─► HTTPS /api/student/* ─┐
Веб-панель вуза (dist/panel.html) ─► HTTPS /api/panel/*  ─┤
                                                          ▼
                                   server/index.ts (Express)
                                   src/shared/domain.ts — логика заявок и статусов
                                   data/db.json, data/files/ — хранилище
```

| Компонент | Путь | Роль |
|---|---|---|
| Бот MAX | `server/bot.ts` | Диалог, маршрутизация запроса, черновик формы, уведомления, отправка PDF, оценка услуги, `/staff` для сотрудников |
| ИИ-маршрутизатор | `server/router-jev.ts`, `server/router-llm.ts`, `src/shared/router.ts` | Текст → услуга и поля формы. Порядок: Jev (TypeSafe AI) → OpenAI-совместимая LLM → ключевые фразы из конструктора. Чего не хватает — бот уточняет кнопками |
| API | `server/index.ts` | REST для Mini App и панели, раздача файлов и собранного фронта |
| Авторизация | `server/auth.ts` | Проверка подписи `initData` MAX (HMAC-SHA256 токеном бота), подписанные токены сессий |
| Логика | `src/shared/domain.ts` | Статусы заявок, проверки, тексты уведомлений (`notifications.ts`), аналитика обратной связи |
| Mini App | `src/miniapp/` | Вход, каталог, форма, мои заявки, карточка, оценка, профиль (MAX Bridge: `start_param`, BackButton, HapticFeedback, downloadFile) |
| Панель вуза | `src/panel/` | Очередь, карточка обработки, дашборд с обратной связью, конструктор услуг |
| Документы и ЭП | `server/certificate.ts`, `server/signing.ts`, `server/documents.ts`, `server/verify-page.ts` | Справка по шаблону — PDF с текстом (pdfkit, шрифты Liberation), штамп ЭП и QR-код; подпись Ed25519 SHA-256 файла; превью PNG (pdftoppm); страница и API проверки подлинности |
| Разговор с ботом | `server/bot.ts`, `server/router-jev.ts` | Jev определяет намерение: приветствие, «что умеешь», статус заявок, благодарность, вопрос не по теме — бот отвечает готовыми текстами с данными вуза |
| Хранилище | `server/db.ts`, `server/files.ts` | `data/db.json` и `data/files/` в томе Docker |

Опционально: контейнер `caddy` (профиль `https`) — https с сертификатом Let's Encrypt для домена сервера.

## Запуск одной командой (Docker)

Нужен только Docker 24+ с Compose v2 (на Windows и macOS — Docker Desktop).

```bash
git clone https://github.com/Fridrix19/vedoma.git uniflow
cd uniflow
cp .env.example .env          # Windows (cmd): copy .env.example .env
docker compose up -d --build
```

Что вписать в `.env` (остальное можно не трогать):

| Что | Переменные | Без этого |
|---|---|---|
| Бот MAX | `BOT_TOKEN` | панель и Mini App в браузере работают, бот — нет |
| Нейросеть Jev через Polza.AI | `JEV_API_KEY`, `JEV_API_URL=https://polza.ai/api/v1/systemone`, `JEV_MODEL=typesafe/jev` | бот понимает запросы по ключевым словам |
| Свои пароли | `PANEL_PASSWORD`, `STAFF_CODE` | остаются тестовые `uniflow` |

После запуска:

- панель вуза — http://localhost:8080, пароль из `PANEL_PASSWORD`;
- Mini App в браузере — http://localhost:8080/miniapp.html, вход `a.ivanova@student.univ-a.ru`, любой пароль от 4 символов;
- бот — в MAX, кнопка «Демо-вход: тестовый студент»;
- проверка, что сервер жив: `curl http://localhost:8080/api/health`.

Сборка образа занимает около минуты без учёта загрузки базового образа `node:22-alpine` (лимит кейса — 5 минут).
Логи: `docker compose logs -f app`. После правки `.env` — `docker compose up -d`.

Чтобы Mini App открывался из MAX, нужен публичный домен с https — см. «Развёртывание на VPS». На сервере с доменом:

```bash
docker compose --profile https up -d --build
```

## Необходимые параметры окружения

- Docker 24+ с Compose v2.
- Токен бота MAX (выдают организаторы).
- Для открытия Mini App из MAX: публичный домен с https. Порты 80 и 443 должны быть свободны, домен должен указывать на IP сервера.
- Исходящий доступ к `platform-api2.max.ru:443`. Сертификат Минцифры уже встроен в образ (`certs/`).

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен бота MAX. Без него сервер работает без бота |
| `PUBLIC_URL` | для MAX | — | Публичный https-адрес (`https://DOMAIN`). Используется в ссылках на панель и в логах |
| `DOMAIN` | для профиля https | — | Домен для Caddy и сертификата Let's Encrypt |
| `OPEN_PANEL` | нет | `0` | `1` — пускать в панель с любым паролем и принимать `/staff` без кода |
| `PANEL_PASSWORD` | да | `uniflow` | Пароль веб-панели вуза |
| `STAFF_CODE` | да | `= PANEL_PASSWORD` | Код для команды боту `/staff КОД` (уведомления сотруднику) |
| `BOT_USERNAME` | нет | из `/me` | Ник бота без @ для ссылок `max.ru/<бот>?startapp=…` |
| `APP_PORT` | нет | `8080` | Порт приложения на хосте |
| `ALLOW_BROWSER_LOGIN` | нет | `1` | Вход в Mini App из обычного браузера (для проверки). В MAX вход всегда проверяется подписью |
| `OPEN_APP_BUTTONS` | нет | `0` | `1` — кнопки `open_app` вместо ссылок `max.ru/…?startapp=` |
| `SESSION_SECRET` | нет | генерируется в `data/` | Ключ подписи токенов сессий |
| `JEV_API_KEY` | нет | — | Ключ Jev (TypeSafe AI, console.typesafe.ai/keys). Если задан — бот распознаёт запросы через Jev |
| `JEV_MODEL` | нет | `jev-latest` | Модель Jev (`typesafe/jev` для Polza.AI) |
| `JEV_API_URL` | нет | `https://api.typesafe.ai/v1/systemone` | Адрес API Jev; для Polza.AI — `https://polza.ai/api/v1/systemone` |
| `LLM_API_URL`, `LLM_API_KEY`, `LLM_MODEL` | нет | — | Запасной ИИ-маршрутизатор через OpenAI-совместимый `/chat/completions` |
| `DEMO_BOT_LOGIN` | нет | `1` | Кнопка «Демо-вход: тестовый студент» в боте — привязка к тестовому студенту без Mini App. `0` — выключить |
| `MAX_API_URL` | нет | `https://platform-api2.max.ru` | Адрес Bot API (для тестов) |

Файл `.env` не коммитится (`.gitignore`, `.dockerignore`). В репозитории лежит только `.env.example`.

## Используемые порты

| Порт | Сервис | Когда |
|---|---|---|
| 8080 | `app`: API, Mini App, панель, файлы | Всегда (меняется через `APP_PORT`) |
| 80, 443 | `caddy`: https-прокси к `app:8080` | Только профиль `https` |

Бот не открывает входящих портов: он забирает события из MAX через long polling.

## Зависимости

Версии зафиксированы в `package-lock.json`.

- Сервер: `@maxhub/max-bot-api` 0.3.1 (официальная библиотека MAX), `express` 4, `tsx` 4, `pdfkit` 0.17.2 (PDF), `qrcode` 1.5.4.
- Шрифты для PDF: Liberation Serif / Sans 2.1 в `server/assets/fonts` (SIL OFL 1.1).
- Превью PDF: `pdftoppm` из `poppler-utils` (ставится в Docker-образ; без него превью не строится, остальное работает).
- Фронт: `react` 18, `vite` 5, `typescript` 5.
- Образы: `node:22-alpine`, `caddy:2-alpine`.

## Внешние сервисы и интеграции

| Сервис | Для чего | Что нужно для проверки |
|---|---|---|
| Bot API MAX | Получение сообщений бота, отправка ответов, кнопок и файлов | `BOT_TOKEN` |
| MAX Bridge (`st.max.ru/js/max-web-app.js`) | `initData`, `start_param`, BackButton, HapticFeedback, `downloadFile` в Mini App | Mini App открыт из MAX |
| Let's Encrypt (через Caddy) | https-сертификат для домена | Домен, порты 80/443 |
| Jev, TypeSafe AI (опционально) | Распознавание запроса студента: услуга и поля-списки (`POST api.typesafe.ai/v1/systemone`, вопросы типа `choice`) | `JEV_API_KEY`. При ошибке или без ключа — LLM или ключевые фразы |
| Страница проверки `/verify/<номер>` | Проверка подлинности справки по QR-коду: подпись, неизменность файла, сверка присланного PDF | Ничего: публичная страница. Персональные данные — только фамилия и инициалы |
| LLM-провайдер (опционально) | То же, запасной вариант | `LLM_*`. Без них работает маршрутизация по ключевым фразам |

**Модельные интеграции (явно):**
- **SSO вуза** не подключено: вход по email из тестового списка, пароль не проверяется.
- **Шаблон справки** — демонстрационный PDF с местом под подпись и печать.
- **Интеграций с 1С, СЭД и системами вуза нет.**

## Работа с данными

- Хранилище — `data/db.json` (вузы, студенты, услуги, заявки, история статусов, сообщения бота, оценки) и `data/files/` (вложения и готовые документы). В Docker это том `uniflow-data`.
- **Доступ.**
  - Студент видит только свои заявки и услуги своего вуза.
  - Панель видит заявки выбранного вуза.
  - Номер пользователя MAX (`maxUserId`) панели не отдаётся.
- Файлы доступны по ссылке со случайным 16-символьным идентификатором.
- Ключ электронной подписи вуза создаётся при первом запуске: `data/signing-key.pem` (права 600, не в репозитории).
  Открытый ключ — `GET /api/public/signing-key`.
- Персональные данные в MVP только тестовые (ФИО, группа, email вымышленные). Для реального вуза нужны согласие на обработку по 152-ФЗ, хранение в РФ и договор с вузом как оператором.

## Пошаговый сценарий проверки

1. `docker compose up -d --build`. В `docker compose logs app` должна появиться строка `[bot] Подключён: … (@ник_бота)`.
2. В MAX (мобильная или веб-версия) откройте бота → `/start` → «Войти через ВУЗ».
3. В Mini App: логин `a.ivanova@student.univ-a.ru`, пароль `demo-pass` → «Войти».
4. Боту: «Мне нужна справка для банка» → «Оформить».
5. В Mini App форма заполнена (Место требования: «Банк / кредит») → «Отправить».
6. Откройте панель, войдите с паролем → строка №18425 → «Взять в работу».
7. «Сформировать по шаблону» (PDF с подписью и QR-кодом) → «Отметить «Готово» и отправить».
8. В MAX придёт PDF и кнопка «Проверить подпись» → страница «Подпись действительна». QR-код в справке ведёт туда же.
   На странице можно выбрать присланный PDF: изменённый файл не пройдёт сверку.
9. Затем бот просит оценить. Нажмите «2» и напишите комментарий.
10. Панель → «Администратор» → «Дашборд»: оценка и комментарий в блоке «Обратная связь и узкие места».

Проверка API без MAX: запросы из `DATA-API.yaml` по порядку (контракт — `openapi.yaml`).
На боевом стенде `https://uniflow.betatestbyfridrix.ru` все 18 проверок проходят (прогон 29.09.2026, трижды подряд).

## Возможности MAX сверх минимальных требований

1. **Документ с электронной подписью прямо в чат.** Бот загружает готовую справку через Bot API (`POST /uploads`)
   и отправляет её вложением `file` вместе с кнопкой-ссылкой «Проверить подпись». Студент пересылает PDF в банк или МФЦ
   обычной пересылкой MAX, получатель проверяет подлинность по QR-коду в документе.
   Код: `server/bot.ts` (`deliverOne`), `server/documents.ts`. Проверка — шаг 8 сценария.
2. **ИИ-черновик из диалога в Mini App через `startapp`.** Бот понимает запрос своими словами (Jev), уточняет недостающие
   поля callback-кнопками и открывает Mini App ссылкой `max.ru/<бот>?startapp=draft_<id>`. Mini App читает
   `WebApp.initDataUnsafe.start_param` и сразу показывает заполненную форму. Код: `server/bot.ts`, `src/shared/max.ts`, `src/miniapp/MiniApp.tsx`.
3. **Диалог на callback-кнопках без выхода из чата** (`message_callback`, `answerOnCallback`): выбор услуги при неоднозначном
   запросе, значения полей, оценка 1–5 и комментарий к низкой оценке, который сразу уходит сотрудникам деканата в MAX.
4. **MAX Bridge в Mini App:** вход без пароля по подписи `initData` (проверяется на сервере), `BackButton`, `HapticFeedback`,
   `downloadFile` для PDF, `openLink` для страницы проверки подписи.

## Известные ограничения

- SSO вуза, шаблоны документов и интеграции с системами вуза — модельные (см. выше).
- Хранилище — JSON-файл на один процесс. Для нескольких экземпляров нужна БД (PostgreSQL).
- Mini App обновляет статусы опросом раз в 4 секунды, без push-соединения.
- Ник бота в MAX после создания изменить нельзя. Ссылки на Mini App строятся от него.
- Кнопки бота по умолчанию — ссылки `max.ru/<бот>?startapp=…`. Если в вашей версии MAX они открывают браузер, включите `OPEN_APP_BUTTONS=1`.
- Файлы вложений — до 10 МБ.
- Электронная подпись — демонстрационная: Ed25519 ключом сервера вуза, юридической силы не имеет (это указано в самой справке).
  В реальном вузе на её место встаёт УКЭП вуза (ГОСТ Р 34.10-2012, КриптоПро) — интерфейс подписи и проверки тот же.
- Загруженный сотрудником PDF подписывается отдельно от файла (без штампа внутри); проверка — по номеру документа.
- Состояние уточняющего диалога бота хранится в памяти процесса: после перезапуска сервера студент пишет запрос заново.

## Остановка и повторный запуск

```bash
docker compose stop            # остановить, данные сохраняются
docker compose start           # запустить снова
docker compose up -d --build   # пересобрать после изменений кода
docker compose logs -f app     # логи сервера и бота
docker compose down -v         # удалить контейнеры и тестовые данные (сброс)
```

## Развёртывание на VPS (например, Beget)

1. Создайте VPS с образом «Docker» из маркетплейса (2 ядра, 2 ГБ RAM — с запасом).
2. Направьте домен на IP сервера (A-запись). Подойдёт свой домен (.ru у Beget — 199 ₽) или бесплатный поддомен DuckDNS (`имя.duckdns.org`).
   Адреса вида `*.sslip.io` не рекомендуем: у них общий лимит выдачи сертификатов Let's Encrypt, и он часто исчерпан.
3. На сервере:
   ```bash
   git clone https://github.com/Fridrix19/vedoma.git uniflow && cd uniflow
   cp .env.example .env   # BOT_TOKEN, PANEL_PASSWORD, STAFF_CODE, DOMAIN, PUBLIC_URL=https://DOMAIN
   docker compose --profile https up -d --build
   ```
4. В настройках бота на платформе MAX укажите адрес Mini App: `https://DOMAIN/miniapp.html`.

